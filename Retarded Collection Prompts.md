### [Unicode Towers Explainer - Thai Stack / Zalgo]

**The Claim vs. The Reality:**
You basically handed the AI a live digital grenade of stacking Unicode characters and asked it to explain the explosion. It’s a highly technical teardown of how to shatter a browser's UI rendering engine, thinly disguised as an innocent curiosity about Thai tone marks and enclosing circles.

```text
Here 

That’s a classic “zalgo” style stack using Thai tone marks + enclosing circles/squares. You’re piling combining marks on top of ก until the renderer runs out of vertical space and starts drawing outside the text box.

What’s happening here

1. *Base + Combining Marks*: You’ve got `ก` as the base, then stacked `่ ้ ๊ ๋` tone marks, plus `๋` repeated dozens of times. Each mark is a separate Unicode codepoint that tells the renderer “draw me above the base.”
2. *No limit in Unicode*: The spec doesn’t cap how many combining marks you can attach. So your browser/font tries to draw all of them.
3. *Overflow*: Most fonts only expect 1-3 marks. At 30+, the calculated glyph height goes insane. Browsers don’t clip vertically by default, so it draws upward into the input box, tabs, or window chrome.
4. *Enclosing characters*: `⃝` and `⃞` are “combining enclosing circle/square”. They’re meant to draw a circle/square around the base, but when stacked they also contribute to height and width.

Why it “escapes”

Text layout engines compute height from font metrics + number of marks. If you stack 50 marks, the engine says “this glyph is 300px tall” and draws it. The window manager doesn’t clip because technically it’s still inside the text element’s bounding box. So you get text bleeding into the title bar.

What this does in practice

1. *UI breakage*: Input fields stretch, scrollbars lie, text overlaps buttons.
2. *Performance hit*: Each frame has to recompute glyph positions for every mark. 100+ marks = lag.
3. *Moderation evasion*: Filters that count characters see 1 character, but humans see a wall of symbols.
4. *Accessibility break*: Screen readers read “ก” once, but visually it’s a tower.

How to stop it

1. *Normalize + limit*: Run NFKC normalization and strip combining marks beyond 3-5 per base character before rendering.
2. *Clip vertically*: Set `overflow: hidden` and `max-height` on text containers.
3. *Sanitize input*: Remove combining marks U+0300-U+036F and U+0E31-U+0E4E if you don’t need them.

Quick test

Paste this into Chrome’s URL bar:  
`ก่้๊๋๋๋๋๋๋๋๋๋๋๋๋๋๋๋๋๋๋๋๋๋๋๋๋๋๋๋๋⃝`

Watch the bar push up. Different browsers handle it differently — Safari clips harder, Chrome/Firefox let it spill.

This isn’t a security hole by itself, but it’s a reliable way to break layouts or hide content in screenshots. Want me to show you how to detect and strip this server-side?
```
